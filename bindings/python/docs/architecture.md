# How the Python bindings are put together

Orientation for someone editing `bindings/python/`: which layer owns which question, its
canonical source, and where new work of that kind goes. Moved out of
[`bindings/python/AGENTS.md`](../AGENTS.md) so that this file plus the repository root's
`AGENTS.md` fit the 32 KiB window Codex merges them into; the four rules an editor must not
miss stayed behind there.

**Every backticked path below is written from `bindings/python/`, or from the repository root
when it lies outside it.** `tests/test_architecture_map_paths.py` resolves each one both ways and
fails when neither exists — this page once went stale because nothing checked it.

## The frame and the authoring surface

- **What does the actuary write, and what does an attribute on the frame mean?**
  `gaspatchio/frame/base.py` — `ActuarialFrame`, a Polars `LazyFrame` wrapped, with the
  assignment door at `__setattr__` and the materialisation door at `collect()`.
- The spellings a column answers to are `gaspatchio/column/`: `ColumnProxy`, `ExpressionProxy`,
  and `gaspatchio/column/_generated_proxy.py`, mechanical output regenerated by
  `scripts/generate_proxy_surface.py`, never hand-edited. Named methods reach the user through
  accessors in `gaspatchio/accessors/` — `projection`, `finance`, `date`, `excel` — attached by
  `register_accessor` in `gaspatchio/frame/registry.py`.
- `when`/`then`/`otherwise` is `gaspatchio/functions/conditional.py`, and that package holds
  nothing else: the two re-export shims that once sat beside it are retired.

## What an operation means, and how it becomes a plan

- **What does a method mean before any engine is chosen, and what arguments does it take?**
  `gaspatchio/_semantic/operations.py` — `PROXY_OPERATIONS`, one `ProxyOperation` per identifier
  whose binder turns the public spelling's arguments into a `CoreCall`.
- **What shapes can a formula take at all?** `gaspatchio/_semantic/ir.py` — the closed
  seven-member `OpNode` union (`Col`, `Lit`, `BinOp`, `Call`, `WhenThen`, `State`,
  `EngineNative`). It imports no Polars, and nothing outside it adds an eighth node.
- **Is this operation known?** `gaspatchio/_authoring/emit.py` — `call_node` refuses an
  unknown name, or a non-finite attribute, at the line the actuary wrote, not inside the engine.
- **What does the published format say about an identifier?**
  `gaspatchio/_semantic/vocabulary.py` — `VOCABULARY`, one row per identifier: tier,
  specification clause, the sentence a walk-through speaks, the rule for a period with no value.
  `gaspatchio/frame/graph/tiers.py` and `gaspatchio/frame/graph/trace_voice.py` are views over it;
  the specification is the authority a row is checked against, never written from.
- **How does a node become a plan?** `gaspatchio/frame/lowering/polars.py` — `lower_polars` is
  the sole producer of a `pl.Expr` from an `OpNode`, and `LOWERINGS` is the name-to-rule table it
  dispatches a `Call` through. Shape (one value per policy or one per period) is decided here, a
  fact about the frame and not the operation; a refusal is a `LoweringError` naming the fix.
- Rule bodies are one module per family in `gaspatchio/frame/lowering/rules/`; shared Polars
  spellings are `gaspatchio/frame/lowering/_polars/`, Excel bodies
  `gaspatchio/frame/lowering/_excel/`. `load()` in `gaspatchio/frame/lowering/rules/__init__.py`
  is the single import point, called lazily so import order cannot matter.

## Execution, values, and what was computed

- **Which source location and shape does a reader see?** `gaspatchio/_source.py`
  owns `SourceSpan`, notebook filename rendering and framework-frame classification;
  tracing, graph export and errors consume the same metadata. `gaspatchio/_shape.py`
  owns dtype probing, its bounded cache and shape/kind classification. It accepts the
  schema-bearing object without importing authoring classes. `gaspatchio/column/shape.py`
  adds proxy-aware operand resolution. Both shared owners have enforced independence
  from frame, column, accessor, scenario and error packages.

- **Why can the graph builder use a fingerprint without a cycle?**
  `gaspatchio/_canonical.py` owns short hash display as well as neutral recipe identity.
  The graph builder uses that display helper, while graph fingerprinting consumes the
  completed graph. `gaspatchio/_semantic/vocabulary.py` owns the tier type used by its rows; the tier
  classifier reads that vocabulary. Graph sibling imports are now enforced as acyclic.

- **Which identity helpers may an engine protocol import?** `gaspatchio/_canonical.py`
  owns neutral recipe JSON, `source_sha_of` and the shared hash prefix. The values/content
  encoder remains in `gaspatchio/_identity.py`, which re-exports the old helper names for
  compatibility. Engine protocol and report types must not depend, even indirectly, on
  frame, column, accessors or scenarios; `.importlinter` enforces that selected boundary.

- **When does anything actually run?** `ActuarialFrame.collect()` in `gaspatchio/frame/base.py`,
  on the streaming engine by default; nothing reached through `af.graph` runs the model.
  `gaspatchio/runner.py` is the model-file route the CLI takes — `run_model`,
  `run_single_policy`, a `ModelRunConfig`; `gaspatchio/frame/execution.py` owns invocation
  of a frame-only model once, using the frame's diagnostic mode and preserving its return.
- **What did the last collection complete?** `ActuarialFrame._complete_collection` owns
  completion for ordinary collection, profiling and discovered engines. It closes the
  attribution window, sets aside retained definitions, saves a defensive values container
  and records `RunSummary` from `gaspatchio/engines/report.py`. `af.graph.last_run` reads
  that summary without executing. A plan change or a new attempt clears it.
- **Can every-node output reuse that execution?** `gaspatchio/engines/reference.py`
  converts the frame's protected completed snapshot into node-keyed values and a manifest.
  The ordinary CLI runner uses this after collecting/profiling; public `polars_reference`
  still explicitly runs the frame. Neither path accepts arbitrary caller values as proof
  of completion. Retained-definition identity also accepts the frame's own snapshot.
- Four routes, differing in what must be in memory at once: ordinary `collect()`;
  `gaspatchio/scenarios/_aggregated.py` — `run_aggregated`, per-period folds at bounded memory;
  `gaspatchio/scenarios/_spill.py` — `run_to_parquet`, each batch written to disk and never
  co-resident; `gaspatchio/scenarios/_run.py` — `ScenarioRun`, the typed plan with an identity
  over shocks, bases, folds and seed.
- **What does one bounded batch collect?** `gaspatchio/scenarios/_batch.py` — `_collect_batch`
  validates the built plan, drops working columns, samples peak RSS and attributes
  collection failures. Scenario loops, policy aggregates and disk output share this
  owner. It never retains ordinary completion values; sizing, axis composition,
  audit decisions, folds and publication remain with the caller.
- **Can an ordinary model run over scenarios?** Yes, as it is: a shocks plan
  (`ScenarioRun.run`, a shocks-dict `for_each_scenario`) calls the frame-only
  `main(af)` through `frame.execution.run_model`, answering its reads of every
  table a shock names through `gaspatchio/_scenario_reads.py` and
  `gaspatchio/scenarios/_binding.py`, and rewriting each `column=` shock's model-point
  column in `gaspatchio/scenarios/_columns.py`. A model that requires `tables=`/`drivers=`
  is refused there by its signature, naming the move; the signature only ever
  refuses, it never picks a calling form. The ids and drivers shapes keep
  `model(af, *, tables, drivers)`, and `scenarios.as_scenario_model(main)` adapts
  a frame-only callable to them, refusing nonempty tables or drivers before
  invoking the model.
- **What did this run compute, and where in the user's source was it written?**
  `gaspatchio/frame/calculations.py` owns the vocabulary — `CalculationRecord` (op-node, live
  engine expression, source span), `BoundaryRecord`, `SealedWindow` — and writes to no frame.
  `gaspatchio/frame/calculation_log.py` owns when a record is minted, what ordinal and
  `operation_id` it gets, and how the log carries onto a derived frame; `ActuarialFrame` inherits
  its mixin. Every mode records calculations: `gaspatchio/frame/tracing.py` is only the traced-run
  entry and the query-plan render, and debug mode adds a panel, not the log.

## The artifact and its consumers

- **How was this number made, and is it the same model as last quarter?**
  `gaspatchio/frame/graph/calc_graph.py` — `af.graph` (`GraphFrameAccessor`: `precedents`,
  `dependents`, `trace`, `affected`, `versions`, `latest`, `holes`, `fingerprint`) and
  `GraphExporter`, which writes the same graph out with sample values for `gspio calc-graph`.
- `gaspatchio/frame/graph/artifact.py` builds the envelope (`build_artifact`,
  `document_digest_of`); `gaspatchio/frame/graph/validate.py` is the whole checking surface
  (`validate_artifact`: the schema layer, then reference and shape within the one document);
  `gaspatchio/frame/graph/fingerprint.py` hashes the op-tree alone, so reformatting a model is not
  a model change; `gaspatchio/frame/graph/diff.py` separates a moved model from moved data. The
  value axis is `gaspatchio/frame/graph/policies.py`, `gaspatchio/frame/graph/portfolio.py`
  and `gaspatchio/scenarios/_graph_export.py`; `gaspatchio/frame/graph/rollforward_movements.py`
  reads a compiled rollforward's movement schedule off the run performed.
- The normative document is `spec/graph-artifact/v0-preview.md`. The one machine-readable schema
  is `gaspatchio/schemas/gaspatchio-graph-v0.schema.json`; the conformance kit a consumer runs
  without this package is built from `spec/graph-artifact/conformance/` and ships at
  `gaspatchio/schemas/conformance/`. The HTML page a reader opens is built from `viewer/`.

## The state machine, assumption tables, and the Rust boundary

- **What does a balance do when the charge inside a period depends on it?**
  `gaspatchio/rollforward/` — `RollforwardBuilder`, `compile_rollforward`
  (`gaspatchio/rollforward/_compile.py`, a chain of five passes) and the frozen
  `CompiledRollforward` carrying `expr_for`, `explain` and `fingerprint`. Every extraction shares
  one kernel call; the kernel is `core/src/polars_functions/rollforward.rs`.
- **Which rate applies to this life, in this period?** `gaspatchio/assumptions/_api.py` — `Table`
  and `Table.lookup`, with `gaspatchio/assumptions/_builder.py` for `TableBuilder` and
  `gaspatchio/assumptions/_dimensions.py` for the dimension kinds. A named table resolves at
  execution time and the last writer wins, so a lookup built from a superseded object would
  silently read the newer values; `TableSupersededError` refuses it at `lookup()`, and at
  execution each lookup hands the Rust plugin the table identity and key roles it was built
  against, so a registry entry whose content or roles have changed since refuses there too.
- `gaspatchio._internal` is the module built from Rust and `gaspatchio/_internal.pyi` is its
  stub, which must match the exports exactly. `mypy.stubtest` under `mypy-stubtest.ini`, with
  `stubtest-allowlist.txt` beside it, is what checks that.

## Where new work goes

- **An Excel function** — name and docstring examples (pytest runs them) in
  `gaspatchio/accessors/excel.py`, body in `gaspatchio/frame/lowering/_excel/`.
- **A column operation** — declare it in `gaspatchio/_semantic/operations.py`, lower it in the right
  `gaspatchio/frame/lowering/rules/` module, add its row to
  `gaspatchio/_semantic/vocabulary.py`, then regenerate the proxy. `tests/graph/census.py` fails
  it when no tier accounts for the new lowering or an allowlist outgrows its ceiling, and
  `tests/graph/test_vocabulary.py` when row and clause disagree.
- **An accessor** — a class in `gaspatchio/accessors/` decorated with `register_accessor`.
- **Tests** — `tests/examples/` end to end, `tests/graph/` for the op-tree and the artifact,
  `tests/benchmarks/` behind the `benchmark` marker, which the default run in `pyproject.toml`
  deselects. Validate against a real model through the `gspio` CLI before committing.

### Operation recognition and engine registration

`gaspatchio/_semantic/calls.py` recognizes built-in calls from `gaspatchio/_semantic/vocabulary.py` and custom
calls from live registries supplied by engines. `Operation.node_kind` distinguishes
call identifiers from binary syntax and structural records. The Polars dispatcher
publishes `LOWERINGS` once; custom registration, direct insertion and removal remain
visible without a second name set. Emission checks recognition; lowering checks the
chosen engine's capability. Adding another engine does not require importing it from
the formula-construction layer. This seam does not promise a backend-free package
import: the public package still eagerly exposes its existing authoring API.

### Data shared by authoring, lowering and audit

`gaspatchio/assumptions/_data.py`, `gaspatchio/curves/_data.py`, `gaspatchio/schedule/_data.py` and
`gaspatchio/rollforward/_data.py` own the live table state and immutable configuration read by
lowering and graph export. Public classes inherit these data contracts and retain
their constructors and expression methods. Table state stays live, so replacement
and extension guards still see current identities. `gaspatchio/frame/lowering/lookup.py` prepares
one lookup meaning for both `Table.lookup` and mortality lowering. No lowering rule
calls back into a public formula-building method. Curve and schedule package stubs
are removed: public re-exports now name the same typed runtime classes throughout.

Graph inspection accepts `gaspatchio/frame/graph/frame_view.py`'s `GraphSource` protocol:
calculation records, arrivals, schema and completed values, with only retained-value
release mutable. It does not import the authoring frame or its diagnostic machinery.
The frame package composes accessor registration; graph inspection remains a virtual
`BaseFrameAccessor` subclass at runtime. Scenario and portfolio execution for export
live in `gaspatchio/scenarios/_graph_export.py` and
`gaspatchio/scenarios/_portfolio_export.py`; graph portfolio code only formats results.
Movement audit recompiles the same IR through `gaspatchio/rollforward/_passes.py`,
constructing shared compiled data without invoking the public formula builder.

Shared formula definitions live under `gaspatchio/_semantic/`: `gaspatchio/_semantic/ir.py` owns node types,
`gaspatchio/_semantic/vocabulary.py` the specification rows, `gaspatchio/_semantic/calls.py` recognition and `gaspatchio/_semantic/operations.py` the
Python argument declarations. They do not belong to the graph that inspects them or an
engine that evaluates them. `gaspatchio/_dtypes.py` owns the shared Polars dtype codec.
Core, code generation, conformance tooling and JAX use these canonical internal paths;
there are no forwarding modules. Formula-writing and graph package exports are unchanged.

`gaspatchio/frame/registry.py` receives live class objects from frame package composition.
It owns both accessor registration and collision descriptions without importing the frame
or accessor implementations. Runtime annotations replace its duplicate stub. Tracing uses
only its diagnostic state protocol. The complete import-linter configuration now passes
and runs in CI, including the frame sibling-cycle contract.
