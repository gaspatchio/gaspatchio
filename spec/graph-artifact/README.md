# The gaspatchio-graph artifact specification

This directory holds the specification for the gaspatchio-graph calculation-graph artifact:
an engine-free, content-addressed record of how every column of an actuarial model was
computed.

| File | What it is |
|---|---|
| [`v0-preview.md`](v0-preview.md) | **The normative document.** Everything a producer or a consumer must do is stated there, and nowhere else. |
| [`LICENSE-CC-BY-4.0`](LICENSE-CC-BY-4.0) | The licence the specification prose is published under — Creative Commons Attribution 4.0 International, verbatim legal code. |
| [`conformance/`](conformance/) | The conformance kit's sources: the standard-library reader, the generators of the operation vectors, the identifier-to-clause map, the boundary review and the archive. What they write lives with the reference implementation, in `bindings/python/gaspatchio/schemas/conformance/` and `…/schemas/vectors/`, and is regenerated by running them, never edited by hand. |

## The schema files

The machine-readable schemas are not in this directory. They live with the reference
implementation, the artifact's own at:

```
bindings/python/gaspatchio/schemas/gaspatchio-graph-v0.schema.json
```

That is the single copy. It is Apache-2.0, the same licence as the rest of the reference
implementation, and it carries an SPDX header saying so. There is deliberately no second copy
here to drift out of step with it; a consumer resolves the identifier
`gaspatchio-graph/v0-preview.3` to that document through the table in section 5 of the
normative document. That table also carries `gaspatchio-graph/v0-preview.1` and
`v0-preview.2`, which resolve to the same file and are refused by it: while the preview is
open the document pins the identifier by `const`, so an older row places a stored artifact
rather than validating one, and section 5 says so where the rows are.

Beside it, `bindings/python/gaspatchio/schemas/facets/` holds the schema of each facet the
reference implementation writes, one file per facet, named as the facet's `_schemaURL` names
it. Each refers to the artifact schema's own definitions -- the facet every facet is, the
narrowing facet, the operation tree -- by `$ref` rather than restating them, so a facet's
schema and the schema that validates the artifact carrying it cannot drift apart.

The run record a scenario run or an aggregation writes beside its output — the audit
sidecar, `schema_version` `"2.1"` — has no machine-readable schema in this preview. Section
13.2 of the normative document is its account, and an artifact names one by the digest of
its bytes, never by a schema.

## Where each published address comes from

An artifact names the addresses below: the specification it was written under in every
facet's `_producer`, the section that says what closes a hole in every hole's `closes_with`,
and each facet's own schema in its `_schemaURL`. Section 6 says a validator never fetches a
facet's two, and none of them has to answer for an artifact to be valid; each is published at
its address all the same, from the one file in this repository the table names, exactly as it
stands, so that a reader who follows one lands on the document it names.
`bindings/python/tests/graph/test_published_addresses.py` holds every address the reference
implementation writes or names to a row here, and every row to a file that is there.

| Address | Published from |

| `https://gaspatchio.dev/spec/graph-artifact/v0-preview.3` | `spec/graph-artifact/v0-preview.md` |
| `https://gaspatchio.dev/schemas/gaspatchio-graph-v0.schema.json` | `bindings/python/gaspatchio/schemas/gaspatchio-graph-v0.schema.json` |

| `https://gaspatchio.dev/schemas/facets/gaspatchio_lowered-v0-preview.1.json` | `bindings/python/gaspatchio/schemas/facets/gaspatchio_lowered-v0-preview.1.json` |
| `https://gaspatchio.dev/schemas/facets/gaspatchio_rollforward_ir-v0-preview.1.json` | `bindings/python/gaspatchio/schemas/facets/gaspatchio_rollforward_ir-v0-preview.1.json` |

The specification is published as a page rendered from its Markdown, and its `#holes`
fragment is the anchor section 7.1 declares; *Before the rendered page is published*, below,
says what the rendering owes it. A schema is published as the JSON file itself, and its `$id`
is its address. What `/schemas/` serves is JSON and nothing else: the four schema files the
table names. The directory they come from also holds the package's `__init__.py` and, under
`conformance/`, the kit's `reader.pyz`, a Python zip application; neither is published there.

## Three modules named for an intermediate representation

Three files in the reference implementation are each called an intermediate representation,
and the names do not say which one answers a given question. This section says which, and none
of it is normative: section 1 says the record is engine-free, and a producer building on a
different stack owes nothing to any of the three. Every claim below was read off the tree on
2026-09-07; the anchors are class, function and field names because line numbers move. Each of the three modules points
back here from its own docstring, so opening one of them is a way in, as is a repository-wide
search for one of the three paths below.

**`bindings/python/gaspatchio/_semantic/ir.py` — what a formula means, independent of the
engine that computes it.** That is the module's own account of itself; *what the author wrote*
is section 8.2's `formula`, the as-written right-hand side, and that field is the normative
audit surface. It defines `OpNode`, the closed union of exactly seven frozen dataclasses
(`Col`, `Lit`, `BinOp`, `Call`, `WhenThen`, `State`, `EngineNative`), and the two traversals
over it, `walk` and `col_refs`. Its whole import list is `math`, `dataclasses`, `typing`
and — under `if TYPE_CHECKING:` — `collections.abc`, and 47 modules of the package imported it
when this was written. A node's `reads` (section 8) is a walk of this tree, and `_references` in
`frame/graph/graph_builder.py` opens its docstring with the shape: *"Two kinds, and the walk
stops at the second."* Its first statement is `extraction = extraction_of(node)`, and the call
that reads a compiled rollforward is yielded whole — *"nothing inside that call is descended
into: the operands there are what the compilation reads"* — so only where there is no such
call does the match arm yield `Col.name` and each of `EngineNative.deps`. The same docstring
says why it is not `col_refs` — *"that function answers 'which columns must the
frame supply', which is a different question from 'what did this formula read' the moment one
of the answers is not a column"*. It is **not** authoritative for what a compiled rollforward
applies: the tree `CalcGraph._compilation` stores for a `rollforward` node is
`Call(_COMPILATION, args=(), attrs=((_FINGERPRINT_ATTR, fingerprint),))` — `_COMPILATION`
resolves to `"rollforward"` and `_FINGERPRINT_ATTR` to `"fingerprint"` — with no arguments at
all, and `frame/lowering/rules/rollforward.py` states the consequence: *"The lowering does not
reconstruct the call from `args`"*.

**`bindings/python/gaspatchio/rollforward/_ir.py` — what the kernel will execute, and which
compilation it is.** `IR` is the frozen record of `states`, `points`, `transitions`,
`schedule`, `batch_axes`, `track_increments`, `lapse_when_all_non_positive` and
`contract_boundary`; `spec_fingerprint(ir)`, a SHA-256 over
`canonical_bytes(canonical_form(ir))`, is what `CompiledRollforward.fingerprint()` returns; the
canonical form leaves `schedule` out, so `register_rollforward` keys the process registry on
that fingerprint paired with `ir.schedule.source_sha()`. Eleven modules imported it when
this was written, nine of them inside `gaspatchio/rollforward/`; the two outside —
`frame/graph/rollforward_ir.py` and `frame/lowering/rules/rollforward.py` — import it under
`if TYPE_CHECKING:` only. What it is **not** is engine-free in the sense section 1 uses of the
record. `State.init`,
`IR.contract_boundary` and every expression-typed field of a transition hold a Polars
expression, and `_canonical._expr_canonical` reduces each to `str(expr)`, so the bytes that
identity is taken over are Polars' own rendering of the expression. `engine_binding` is
deliberately not a field of `IR`: `derive_engine_binding` recomputes it every time
`canonical_form` runs, by walking each expression's own serialised tree and accepting only
the closed subset — anything else, an unrecognised node kind included, stamps `'polars'`.

**`bindings/python/gaspatchio/frame/graph/rollforward_ir.py` — what the artifact says about a
compiled machine.** It is a reading rather than a third representation: `rollforward_ir_facet`
opens with `ir = compiled.ir` and projects that `IR` through `classify_operand_expression`,
whose signature is `(expr: pl.Expr, …) -> OpNode`. What it produces is the
`gaspatchio_rollforward_ir` facet, which `_envelope_facets` emits behind
`if profile != PROFILE_EXECUTABLE: return {}` and announces by calling `FacetLedger.record`
on that name — the one call site passes no `required`, and `record`'s `required` argument
defaults to `False`, so the name reaches `facets_used` and never `facets_required` (section
6). The facet is inside `document_digest`, which section 13.1 takes with only that one member
removed, and inside no fingerprint:
`graph_fingerprint`'s three sections are node-id/fingerprint pairs, assumption content hashes
and unaccounted column names. Where the compiled artefact is out of the exporting process's
reach, `_compilations_in` logs and passes over it and `rollforward_ir_for` returns `None` —
so the facet is absent rather than empty.

**Where two of them carry one fact, `rollforward/_ir.py` is upstream.**
`gaspatchio.frame.lowering` names both directions in one breath: `lower_polars` is *"the sole
producer of Polars expressions from an `OpNode`"*, and *"`to_node` is the opposite door"*. Two
of the eight kinds of operand that door answers for are sealed as
`EngineNative(engine="polars", text=str(expr), deps=tuple(expr.meta.root_names()))` — a raw
`pl.Expr`, and a value the op-tree has no literal form for. A proxy contributes the node it
already carries, so `af.claims = af.sum_assured * af.pols_death` reaches the tree as a `BinOp`
of two `Col`s with nothing sealed in it. At the rollforward the increments and the contract
boundary come back as nodes as well, and the reason is the compiler rather than the reader:
`_passes._single_column_name` refuses either if it is anything but a bare `col("name")`, so
`classify_operand_expression` always has one to read back — as a `Col`, or as a `State` where
both halves of the `"<state>@<point>"` spelling `StateRef.canonical_name()` writes name a
declared state and a declared point. A state's opening value is under no such rule: `_passes`
takes it raw, `[s.init for s in ir.states]`, so a fund opening at `pl.lit(0.0)` reaches the
artifact as an `engine_native` node. The machine itself is compiled before the tree is written
from it — `CompiledRollforward` stamps the node with
`(("fingerprint", fingerprint), ("schedule", schedule), *attrs)` from the pair
`register_rollforward(self)` returns, `_run_of` reads that pair back off `Call.attrs`, and
`_declared_states` spends it, resolving the compilation to
`tuple(state.name for state in compiled.ir.states)`. The two classes named `State` are the same
overlap seen twice: `rollforward/_ir.py`'s `State(name, init)` is the declaration, and
`gaspatchio/_semantic/ir.py`'s `State(name)` is a reference to one — minted on the lowering path by
`classify_operand_expression` and by `_target_state_node` off an operation's own `target`, and
minted off that path by `op_json.op_node_from_json`, which builds one from a wire document with
no declaration consulted at all.

## Before the rendered page is published

The Markdown here is the source; publishing it produces HTML, and the HTML has to satisfy
one thing the source cannot state about itself. Check it against the rendering before the
page goes up.

- **Section 7.1 declares an explicit `#holes` anchor.** Every artifact the reference
  implementation writes points each hole at
  `https://gaspatchio.dev/spec/graph-artifact/v0-preview.3#holes` — that is the `closes_with`
  URI, emitted from one constant in `bindings/python/gaspatchio/frame/graph/artifact.py`. A
  renderer that derives anchors from headings numbers the holes section
  `#71-the-holes-section` instead, and a reader following a hole to the page would land on
  the page with nothing under them. The anchor is added to the page rather than the URI
  changed in the producer: artifacts carrying that string are already written and cannot be
  re-issued, whereas the anchor costs the page one line. The fragment is in no digest —
  `graph_fingerprint` hashes hole *names* and nothing else about a hole — so neither
  direction moves an identity, and this one moves no bytes at all.
